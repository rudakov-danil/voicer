## Сделано

### Этап 1 — дизайн-система на всех экранах
- Токены концепта в `services/frontend/src/index.css`. Старые имена (`--primary`, `--bg`, `--text`…) работают как псевдонимы новых.
- Шрифт Onest раздаётся с нашего сервера (`@fontsource-variable/onest`), без Google Fonts.
- `Sidebar` и `Topbar` по концепту. До 1180 px сайдбар сворачивается в иконки, до 760 px прячется: вместо него мобильная шапка с меню.
- EN/RU: модуль `src/i18n/` — `t()` / `L()` / `plural()` и перевод DOM по словарю `en.ts`. Узлы с `translate="no"` (имена, данные) не переводятся.
- Телефония скрыта флагом `TELEPHONY_ENABLED = false` в `src/lib/terms.ts`.
- Подсветки в расшифровке, вкладки правил в «Скриптах», цвета типов возражений в «Аналитике» переведены на токены палитры.
- Список разговоров на телефоне показывается карточками.
- Удалены `ScoreBadge`, старый `AudioPlayer`, `SellerDrawer`, `HeatmapStrip`, `IntelligencePage`, `TrainingPage`, палитра аватаров и CSS этих компонентов.
- Страницы грузятся отдельными чанками (`React.lazy`): основной бандл 416 КБ вместо больше 1 МБ. Самый тяжёлый чанк — «Аналитика» (recharts в «Подробных отчётах»).

### Страница разговора `/conversations/:id`
- Шапка с вердиктом, плеер-консоль с дорожками и волной, расшифровка с пометками, разбор балла, допродажа, возражения и нарушения, ссылка на момент `?t=`.
- Волна проверена на синтетической записи под таймкоды реплик: столбики повторяют громкость, «Пропускать паузы» и перемотка работают.
- «Разобрать с продавцом»: разговор попадает в план разбора продавца. Повторный клик убирает его из плана.
- Комментарии руководителя с приложенным моментом записи, отметка «Разобрано».
- «День продавца»: все разговоры продавца за ту же дату на шкале часов, цвет — исход, клик открывает разговор.
- Резюме ИИ по пунктам: «Итог», «Риск претензии», «Что сработало», «Что поправить». Старые резюме показываются как раньше, с подсказкой обновить.
- Узкие экраны: вердикт в две колонки, дорожки плеера уже, линейка подстраивается под ширину.
- Быстрый просмотр из списка: строка открывает панель справа с «отпечатком», итогом ИИ, моментами и этапами. Ссылка `?open=<id>`, Ctrl/⌘-клик открывает полную карточку.

### «Обзор» (`dashboard.html`)
- «Пульс недели»: разговоры по получасам за 7 дней по времени магазинов, красным — требующие внимания, таблица-двойник.
- «Очередь на разбор»: сначала нарушения, потом низкий балл, с цитатой, «отпечатком» и кнопкой на момент записи. Вкладки «Все / Нарушения / Низкий балл».
- Показатели с рядами за 12 недель и изменением к прошлому такому же периоду: конверсия, балл, допродажа, отработка возражений.
- Исходы, нарушения по правилам, магазины, где теряем баллы, возражения, кто растёт и кто проседает.

### Остальные экраны
- Команда: магазины-фильтры, рейтинг с 12-недельной динамикой, профиль продавца: балл против медианы сети, этапы скрипта, зоны развития с лучшим примером в сети, план разбора, последние разговоры.
- Скрипты: «Как складывается балл», тепловая карта «продавец × этап», совет и лучший пример на каждом этапе.
- Аналитика: конверсия магазинов по неделям, что влияет на покупку, где уходят покупатели, нагрузка по часам, ответы на «дорого», доля речи против конверсии. Прежние отчёты остались ниже, в «Подробных отчётах».
- Комплаенс: показатели, журнал нарушений со статусом разбора (берётся из плана разбора), правила с числом нарушений. Управление правилами и шаблоны — ниже на странице.
- Настройки: одна страница с разделами «Организация», «Магазины», «Пользователи и роли», «Оповещения», «Приватность и хранение».
- Сайдбар: подборки со счётчиками, у организации — число магазинов.

### Бэкенд
- `analytics-engine`: миграция `0009_coaching_items` (таблица `analytics.coaching_items`), промпт резюме по пунктам. Повторный анализ переносит пункты разбора на новый разговор.
- `dashboard-service`, новые эндпоинты:
  - `GET/POST /conversations/{id}/coaching`, `PATCH/DELETE /coaching/{id}`, `GET /coaching` — план разбора и комментарии;
  - `GET /conversations/{id}/day` — день продавца;
  - `GET /overview/pulse`, `/overview/trends`, `/overview/violations`, `/overview/step-losses`;
  - `GET /sellers/{id}/benchmark` — продавец против сети;
  - `GET /scripts/{id}/breakdown` — тепловая карта скрипта;
  - `GET /insights` — блоки «Аналитики».
- В список разговоров добавлены `order=risk`, подборка `low_score`, цитата нарушения, неотработанное возражение, самый слабый этап. В `/overview` — покупки, допродажа, отработка возражений. В `/sellers` — покупки и разговоры с нарушениями. В журнал комплаенса — время записи и статус разбора.
- Новая настройка `LOCAL_TZ` (по умолчанию `Europe/Moscow`): по ней считаются получасы «Пульса» и часы нагрузки.

## Для проверки локально
- Фронтенд: конфигурация `frontend` в `.claude/launch.json` (порт 3000, проксирует `/api` на локальный стек на :80).
- Изменения бэкенда: `docker compose build dashboard-service && docker compose up -d dashboard-service`, миграции — `./start.sh`.
- Во фронтенде у каждого `.tsx` есть скомпилированный `.js` рядом, и Vite берёт `.js`. После правок обязательно запускать `npx tsc` в `services/frontend`.
- В демо-дампе разговоры за май–июнь. Чтобы экраны с периодом не были пустыми, даты можно сдвинуть в локальной базе (`session_date`, `started_at`, `analyzed_at`).
- Английский интерфейс: `?lang=en`. Оставшиеся русские строки ищутся проходом по страницам: всё вне `translate="no"` с кириллицей должно быть в `src/i18n/en.ts`.
