# Фронтенд — экраны, компоненты, UX-логика

## Технологии

- **React + TypeScript** — компонентный SPA с типизацией
- **Адаптивный веб** — отзывчивая вёрстка под мобильные экраны; нативных приложений iOS/Android нет в MVP
- **Vite** — быстрая сборка
- **Recharts** — графики (линейные, donut, bar)
- **shadcn/ui** — базовые UI-компоненты
- **TanStack Table** — таблицы с фильтрацией, сортировкой, пагинацией
- **Zustand** — глобальный стейт (аутентификация, фильтры)
- **Axios** — HTTP-клиент с автоматическим обновлением JWT

## Экраны

### 1. Обзор (Dashboard / Overview)

**URL:** `/`

Главный экран для всех ролей. Отображает сводную картину.

**Компоненты:**
- **Селектор периода** — 7 / 30 / 90 дней (глобальный, применяется ко всем виджетам)
- **Дропдаун «Магазин»** — для ролей `director` и `admin`: позволяет выбрать конкретный магазин или «Все магазины»; применяется ко всем виджетам страницы
- **3 карточки метрик** с трендом (стрелка вверх/вниз):
  - Всего разговоров
  - Конверсия (%)
  - Средний скоринг (%)
- **Линейный график трендов** — все 3 метрики по дням за период
- **Donut chart «Исходы разговоров»** — покупка / отложено / отказ по цене / конкурент / неизвестно
- **Таблица последних разговоров** — 10 записей, кликабельные (открывают Drawer)
- **Блок алертов** — карточки с предупреждениями (низкий скоринг, серия отказов)
- **Иконка колокольчика** в топбаре — показывает количество активных алертов, при клике раскрывает список

**UX-логика:**
- При изменении периода — все виджеты обновляются одновременно
- Блок алертов показывается только если есть реальные проблемы, иначе скрыт
- Алерты доставляются только через интерфейс (колокольчик + блок на дашборде). Email и push-уведомления не поддерживаются в MVP
- Кликабельная карточка метрики навигирует к соответствующему разделу
- Пороги алертов настраиваются в разделе «Настройки» (не хардкодятся в UI)

### 2. Разговоры (Conversations)

**URL:** `/conversations`

Список всех разговоров с детальным просмотром.

**Фильтры (панель сверху):**
- Магазин (для director, admin, rop)
- Продавец
- Исход разговора (покупка / отказ / отложено / конкурент)
- Диапазон дат
- Диапазон скоринга (например, только <70%)

**Таблица:**

| Колонка | Описание |
|---------|---------|
| Дата | Дата и время разговора |
| Продавец | Имя + аватар-инициалы |
| Тема | Товар/услуга разговора |
| Длительность | В формате 5:32 |
| Скоринг | Прогресс-бар с цветом (зелёный/жёлтый/красный); если у магазина нет активного скрипта — вместо прогресс-бара показывается tooltip «Нет скрипта» |
| Исход | Цветной тег |

**Пагинация:**
- По умолчанию отображается **20–50 записей** на странице (настраиваемый выбор)
- Тип: **номерная пагинация** — `« 1 2 3 4 5 »`
- Без бесконечного скролла; пользователь видит номер страницы и может перейти на любую

**Детальная карточка разговора (Drawer):**

Открывается справа при клике на строку таблицы.

**Транскрипт:**
- Разговор разбит по ролям (Продавец / Клиент)
- Таймкоды рядом с каждым фрагментом
- Подсветка возражений красным цветом
- Клик по таймкоду — перемотка аудиоплеера

**Чек-лист скрипта:**
- Список всех этапов скрипта
- Для каждого: название, прогресс-бар (%), detected/missed, цитата-доказательство

**Карточка исхода:**
- Тип исхода (покупка, отложено, отказ...)
- Confidence score
- Тема разговора
- Длительность

**Возражения:**
- Список найденных возражений с типом, статусом закрытия и техникой

**Аудиоплеер:**
- Стриминговое воспроизведение — только диапазон разговора (по `start_time` / `end_time`)
- Синхронизация позиции с транскриптом (клик на таймкод перематывает плеер)

> **Экспорт данных (CSV/Excel):** не реализован в MVP. Планируется в v2.

### 3. Команда (Team)

**URL:** `/team`

**Рейтинг продавцов (Leaderboard):**
- Карточки продавцов в порядке убывания конверсии
- Топ-3 выделены медалями (золото, серебро, бронза)
- На карточке: имя, аватар, конверсия, скоринг, количество разговоров
- Клик → Drawer с профилем продавца
- **Уволенные продавцы:** по умолчанию скрываются из рейтинга; переключатель «Показывать уволенных» позволяет включить их в список

**Профиль продавца (Drawer):**
- Личные метрики за выбранный период
- Радар-чарт или список по этапам скрипта — какие выполняются хорошо, какие западают
- **Блок «Зоны развития»** — этапы скрипта, отсортированные от худшего результата к лучшему:
  - Для каждого проблемного этапа: название, оценка (%), и `recommendation_text` из скрипта
  - Этапы с оценкой ≥ 80 показывают похвалу без рекомендации
  - Этапы с оценкой < 80 показывают шаблонную рекомендацию
- Последние 5 разговоров продавца

**Сравнение магазинов (для director, admin, rop):**
- Таблица магазинов: количество продавцов, разговоров, средний скоринг, конверсия
- Позволяет быстро сравнить эффективность точек продаж

### 4. Скрипты (Scripts)

**URL:** `/scripts`

Доступен ролям `director`, `admin`, `manager`.

**Список шаблонов:**
- Карточки или таблица: название, количество этапов, статус (активен/черновик), дата создания
- Кнопка «Создать новый скрипт»

**Редактор скрипта:**
- Название и описание шаблона
- Список этапов — drag & drop для изменения порядка
- Для каждого этапа: название, описание, вес (числовой ввод), тоггл «обязательный», поле рекомендации
- Валидация: сумма весов должна быть = 1.0 (показывается в реальном времени)
- Кнопки: Сохранить / Активировать / Деактивировать

**Назначение скриптов продавцам:**
- Выбор продавца → список доступных скриптов → назначить с пометкой «обязательный» или «контекстный»

## Глобальный стейт (Zustand)

### authStore

```typescript
{
  user: User | null,
  role: 'director' | 'admin' | 'rop' | 'manager' | null,
  organization_id: string | null,
  store_id: string | null,       // только для manager
  accessToken: string | null,
  login: (email, password) => Promise<void>,
  logout: () => void,
  refreshToken: () => Promise<void>
}
```

### filterStore

```typescript
{
  period: 7 | 30 | 90,           // глобальный период дашборда
  selectedStoreId: string | null, // выбранный магазин (для admin/director/rop)
  setPeriod: (period) => void,
  setStore: (storeId) => void
}
```

## Axios-интерцептор (JWT Refresh)

Все API-запросы идут через настроенный Axios-инстанс. При получении ответа `401 Unauthorized`:
1. Интерцептор автоматически запрашивает новый access token через refresh token
2. Повторяет исходный запрос с новым токеном
3. Если refresh тоже отказал — пользователь перенаправляется на страницу входа

Это происходит незаметно для пользователя — сессия продолжается автоматически.

## Права доступа на уровне UI

Компоненты, требующие определённой роли, оборачиваются в `<RoleGuard>`:

```typescript
// Только manager видит редактор скриптов
<RoleGuard roles={['manager']}>
  <ScriptEditor />
</RoleGuard>

// Director, admin и rop видят сравнение магазинов
<RoleGuard roles={['director', 'admin', 'rop']}>
  <StoreComparison />
</RoleGuard>

// Только admin видит раздел настроек
<RoleGuard roles={['admin']}>
  <SettingsPage />
</RoleGuard>
```

Если пользователь пытается открыть недоступный URL — происходит редирект на главную страницу.
