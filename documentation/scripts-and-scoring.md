# Скрипты продаж и скоринг

## Что такое скрипт продаж в VoiceIQ

Скрипт продаж — это формализованный сценарий разговора, которому должен следовать продавец. В VoiceIQ скрипт задаётся как набор этапов с весами — по ним система оценивает каждый разговор.

Скрипты создаются и редактируются через интерфейс платформы (раздел «Скрипты»).

---

## Два уровня скриптов

### Скрипты уровня организации (`scope = org_level`)

- Создаются `director` или `admin`
- Видны всем пользователям организации
- Назначаются продавцам любым `manager`, `admin` или `director`
- Используются как базовые стандарты для всей компании

### Скрипты уровня менеджера (`scope = manager_level`)

- Создаются `manager`
- Видны только создателю + `director`/`admin`
- Назначаются продавцам только тем менеджером, который их создал (или `director`/`admin`)
- Используются для индивидуальной настройки под конкретных продавцов

> **Правило видимости:** менеджер видит список скриптов = свои скрипты (`scope = manager_level`, `created_by = self`) + все скрипты организации (`scope = org_level`). Скрипты других менеджеров недоступны.

---

## Структура скрипта

### Шаблон скрипта (Script Template)

Верхний уровень — это шаблон:
- **Название** — понятное имя, например "Скрипт продажи смартфонов"
- **Описание** — контекст применения
- **Уровень** — `org_level` или `manager_level`
- **Статус** — активен или деактивирован (soft delete)
- **Создатель** — `created_by` (UUID пользователя)

**Нет единственного «активного» скрипта:** продавцу может быть назначено несколько скриптов одновременно. Все они применяются при анализе каждого разговора.

**Заморозка содержимого:** скрипт, назначенный хотя бы одному продавцу, не удаляется физически. При деактивации устанавливается `is_active = false`. Оценки по нему в истории сохраняются.

**Шаблоны «из коробки»:** при создании новой организации автоматически создаётся несколько базовых шаблонов (`scope = org_level`). Менеджер может назначить один или несколько продавцу сразу или создать свой.

### Этапы скрипта (Script Steps)

Каждый шаблон содержит упорядоченный список этапов. Набор этапов **произвольный** — создатель скрипта сам придумывает названия и количество. Для каждого этапа задаётся:

| Поле | Тип | Описание |
|------|-----|---------|
| `name` | строка | Название этапа, например "Выявление потребностей" |
| `description` | текст | Что именно должен сделать продавец на этом этапе |
| `weight` | float (0–1) | Вес этапа в итоговом балле этого скрипта |
| `is_required` | bool | Обязательный ли этап (влияет на алерты) |
| `step_order` | int | Порядковый номер (для отображения) |
| `recommendation_text` | текст | Шаблонная рекомендация для продавца при низком выполнении этого этапа |

**Важное ограничение:** сумма весов всех этапов одного скрипта должна равняться 1.0. Это проверяется при сохранении.

### Пример типичного скрипта для розничной торговли

| № | Этап | Вес | Обязательный |
|---|------|-----|-------------|
| 1 | Приветствие | 0.10 | Да |
| 2 | Выявление потребностей | 0.25 | Да |
| 3 | Презентация продукта | 0.25 | Да |
| 4 | Работа с возражениями | 0.20 | Нет |
| 5 | Предложение апсейла | 0.10 | Нет |
| 6 | Закрытие сделки | 0.10 | Да |
| **Итого** | | **1.00** | |

> Этапы "апсейл", "сбор контакта", "предложение рассрочки" — это просто обычные этапы скрипта. Никакой отдельной структуры для них нет.

## Привязка скриптов к продавцам

Скрипты назначаются **конкретному продавцу** (`seller`), а не магазину.

Одному продавцу назначается несколько скриптов. При назначении каждый скрипт помечается как **обязательный** или **контекстный**:

### Обязательный скрипт (`is_mandatory = true`)

- Применяется к **каждому** разговору продавца без исключений
- Если продавец не выполнил этапы — получает 0 баллов по этому скрипту
- Пример: базовый скрипт с приветствием и выявлением потребностей

### Контекстный скрипт (`is_mandatory = false`)

- На шаблоне скрипта задаётся `context_description` — текстовое описание, когда этот скрипт применим
  - Пример: `"Применять при продаже смартфонов, телефонов и мобильных устройств"`
- Перед анализом разговора LLM оценивает: **подходит ли этот скрипт к данному разговору?**
- Если да — скрипт применяется и входит в скор
- Если нет — скрипт **пропускается**, в скор не входит, продавец не штрафуется
- Пример: скрипт апсейла холодильников не применяется к разговору про смартфоны

Назначает скрипты: `manager` (только своим продавцам), `director`/`admin` (любым продавцам организации).

## Как работает скоринг

### Шаг 1 — Отбор применимых скриптов

Перед оценкой система определяет, какие скрипты войдут в анализ:

1. **Обязательные** — применяются все без исключений
2. **Контекстные** — для каждого LLM отвечает на вопрос:
   > «Подходит ли контекст скрипта `{context_description}` к этому разговору? Ответь: yes/no и обоснование.»
   - `yes` → скрипт применяется
   - `no` → скрипт пропускается

### Шаг 2 — Расчёт балла за один скрипт

LLM анализирует транскрипт применительно к каждому этапу скрипта:
- `score` (0–100): насколько хорошо выполнен этап
- `detected` (true/false): был ли этап в разговоре
- `evidence`: цитата из транскрипта

Балл по скрипту = взвешенная сумма:
```
script_score = Σ (score_i × weight_i) для всех i этапов
```

### Шаг 3 — Итоговый балл разговора (overall_score)

```
overall_score = среднее по всем ПРИМЕНЁННЫМ скриптам
```

**Пример:**
```
Продавцу назначено 3 скрипта:
  Обязательный "Базовый":           применён → script_score = 82
  Контекстный "Апсейл смартфонов":  применён (разговор про телефон) → script_score = 70
  Контекстный "Апсейл холодильников": пропущен (LLM: не применимо)

overall_score = (82 + 70) / 2 = 76
```

**Если ни один контекстный не подошёл:**
```
overall_score = среднее только по обязательным скриптам
```

**Если нет ни обязательных, ни применимых контекстных:**
```
overall_score = null (скоринг не выполнялся)
```

### Что хранится в базе

- В `conversations`: `overall_score` — итоговый балл (среднее по применённым скриптам)
- В `conversation_script_results`: по одной записи на **каждый назначенный** скрипт — `script_score`, `was_applied` (применён или пропущен), `skip_reason` (причина пропуска от LLM)
- В `conversation_scores`: детализация по этапам только для **применённых** скриптов

Детализация нужна для отображения в карточке разговора: пользователь видит не просто "76%", а по каждому скрипту и каждому этапу — что выполнено, что нет и почему.

## Какой скрипт используется при анализе

При запуске анализа берутся **все скрипты, назначенные продавцу на момент постановки задания в очередь** `queue.analyze`.

**Историческая неизменность:** оценки фиксируются навсегда в момент анализа. Добавление нового скрипта продавцу не пересчитывает старые разговоры. Удаление назначения — тоже.

**Повторный анализ:** доступен через `POST /api/v1/analytics/reanalyze/{id}`. При повторном анализе берутся скрипты, актуальные **на момент повторного запуска**.

---

## Отображение деактивированного скрипта в карточке разговора

Если скрипт деактивирован — в карточке разговора он всё равно отображается **полностью**: название, список всех этапов и оценки по каждому. Исторические данные не скрываются.

---

## Soft Delete и история скоринга

Скрипты нельзя удалить физически. При удалении устанавливается `is_active = false` (soft delete). Все исторические оценки по этому скрипту сохраняются.

---

## Рекомендации по этапам скрипта

Для каждого этапа скрипта можно задать `recommendation_text` — шаблонную фразу с советом для продавца.

### Логика отображения

| Оценка этапа | Что показывается продавцу |
|--------------|--------------------------|
| ≥ 80 | Похвала: «Отлично, продолжай в том же духе» |
| 50–79 | Шаблонная рекомендация из `recommendation_text` |
| < 50 или `detected = false` | Шаблонная рекомендация с пометкой «Требует внимания» |

**Сортировка:** этапы в блоке рекомендаций выводятся от худшего результата к лучшему.

**MVP:** рекомендации — статичные шаблонные тексты. В v2 планируется генерация через LLM.

## Управление скриптами через API

| Действие | Метод | Endpoint |
|----------|-------|----------|
| Список шаблонов | GET | `/api/v1/scripts/templates` |
| Создать шаблон | POST | `/api/v1/scripts/templates` |
| Получить шаблон с этапами | GET | `/api/v1/scripts/templates/:id` |
| Обновить шаблон | PUT | `/api/v1/scripts/templates/:id` |
| Деактивировать (soft delete) | PATCH | `/api/v1/scripts/templates/:id` |
| Назначить скрипт продавцу | POST | `/api/v1/scripts/assignments` |
| Снять скрипт с продавца | DELETE | `/api/v1/scripts/assignments/:id` |
| Скрипты продавца | GET | `/api/v1/scripts/assignments?seller_id=uuid` |
| Все скрипты продавца (для analytics) | GET | `/api/v1/scripts/for-seller?seller_id=uuid` |
