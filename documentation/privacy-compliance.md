# Приватность и соответствие 152-ФЗ

## Контекст

VoiceIQ записывает разговоры продавцов с клиентами в торговых залах. Это персональные данные обеих сторон. Платформа проектируется с учётом требований Федерального закона №152-ФЗ «О персональных данных».

Раздел описывает: какие данные собираются, как они защищаются и что обязан сделать оператор.

---

## Что является персональными данными в VoiceIQ

| Категория | Данные | Где хранятся |
|-----------|--------|-------------|
| Данные сотрудников | Имя, дата найма, голос (в записи) | `sellers`, `recordings` |
| Данные клиентов | Голос (в записи), упоминания ФИО/номеров/данных карт | `recordings`, `transcripts` |
| Данные пользователей системы | Email, хеш пароля, история входов | `users`, `refresh_tokens` |

---

## Требования к оператору

### 1. Согласие сотрудников

**Что требуется:** каждый продавец, который будет носить аудиобейдж, должен дать письменное согласие на запись своих разговоров.

**Реализация:**
- Факт получения согласия фиксируется в системе: поле `employee_consent` в `privacy_settings`
- Датируется и хранится в HR-системе (вне платформы)
- Система не блокирует работу при отсутствии флага, но это ответственность администратора магазина

### 2. Уведомление клиентов

**Что требуется:** клиенты должны знать о том, что разговор записывается.

**Реализация:**
- Информационные таблички при входе в магазин и у касс
- LED-индикация на самом бейдже — когда идёт запись, горит световой индикатор
- Настройка `client_notification` в системе фиксирует, что уведомление организовано

### 3. Срок хранения данных

**Что требуется:** данные нельзя хранить дольше, чем необходимо для достижения целей обработки.

**Реализация:**
- Администратор выбирает срок хранения для каждого магазина: **90 / 180 / 365 дней**
- Настройка `retention_days` в `privacy_settings`
- Cron-задача (запускается раз в сутки) удаляет:
  - Аудиофайлы из MinIO
  - Транскрипты из PostgreSQL
  - Для которых `recorded_at < NOW() - retention_days`
- **Удаляются:** аудиофайлы из MinIO, транскрипты (`transcripts`, `transcript_segments`), метаданные записей (`recordings`)
- **Не удаляются:** аналитические данные (`conversations`, `conversation_scores`, `objections`) — они не содержат персональных данных и хранятся постоянно для сохранения исторических трендов

### 4. Анонимизация персональных данных в транскриптах

**Что требуется:** минимизировать объём хранимых ПД клиентов.

**Реализация:**
- При включённом `anonymize_pii` — после транскрибации запускается автоматическая маскировка:
  - Номера телефонов → `[PHONE]`
  - Номера банковских карт → `[CARD]`
  - Паспортные данные → `[PASSPORT]`
  - ФИО клиента (если распознаётся) → `[NAME]`
- Маскировка выполняется на уровне сохранения в `transcripts` — исходный текст не хранится
- Аудиозапись при этом не изменяется (техническое ограничение)

### 5. Шифрование данных

**Хранение:**
- Аудиофайлы в MinIO: **AES-256** шифрование на уровне объектного хранилища
- Данные в PostgreSQL: шифрование диска на уровне сервера

**Передача:**
- Все соединения: **TLS 1.3**
- API Gateway принимает только HTTPS
- Бейджи отправляют данные по HTTPS

**Ключи:**
- Управление ключами через HSM или Yandex Cloud KMS (в продакшене)
- Ротация ключей — раз в год или при подозрении на компрометацию

### 6. Локализация данных (в РФ)

**Что требуется:** персональные данные граждан РФ должны обрабатываться и храниться на серверах в России.

**Реализация:**
- Весь стек для продакшена разворачивается в **Yandex Cloud** (регион Россия)
- **STT — Whisper self-hosted** на собственном GPU-сервере: данные не передаются ни в какие внешние API
- **LLM — локальные модели** через Ollama (MVP) / vLLM (продакшн) на собственном GPU-сервере: данные не покидают инфраструктуру клиента
- Зарубежные облачные LLM-провайдеры (OpenAI, Anthropic и т.п.) **не используются** — запрещено для реальных данных с ПД
- Бэкапы: также в Yandex Cloud

## Настройки приватности в системе

Управляются через раздел «Настройки → Приватность» (только роль `admin` организации).

| Параметр | Тип | Описание |
|----------|-----|---------|
| `employee_consent` | toggle | Сотрудники ознакомлены и дали согласие на запись |
| `client_notification` | toggle | Клиенты уведомляются о записи (таблички, индикация) |
| `anonymize_pii` | toggle | Автоматически маскировать ПД в транскриптах |
| `retention_days` | select | Срок хранения: 90 / 180 / 365 дней |

**Уровни настроек:**
- **Уровень организации** (`store_id = NULL` в `privacy_settings`): задаёт значения по умолчанию для всех магазинов
- **Уровень магазина** (`store_id = <конкретный магазин>`): переопределяет настройки организации для конкретного магазина
- Если у магазина нет своих настроек — используются настройки организации (наследование)

## Безопасность платформы

### Аутентификация и авторизация

- JWT access token: TTL 15 минут (короткий срок снижает риск компрометации)
- Refresh token: TTL 30 дней, хранится в httpOnly cookie (недоступен JavaScript)
- При logout: refresh token немедленно инвалидируется через Redis blacklist
- RBAC: каждый запрос проверяется на соответствие роли пользователя
- Изоляция по магазину: пользователь не может получить данные чужого магазина

### Rate Limiting

- API Gateway ограничивает: **100 запросов в минуту** на одного пользователя
- Защита от brute-force на `/login`: блокировка после 5 неудачных попыток

### Защита от угроз

| Угроза | Защита |
|--------|--------|
| SQL Injection | Parameterized queries через SQLAlchemy ORM |
| Brute-force | Rate limiting + блокировка аккаунта |
| Утечка токенов | Короткий TTL + Redis blacklist |
| MITM | TLS 1.3 для всех соединений |
| Несанкционированный доступ | RBAC + изоляция по organization_id + store_id |
| DDoS | Rate limiting на API Gateway |

### Аудит-лог

Все критические действия логируются с привязкой к пользователю:
- Вход и выход из системы
- Создание/изменение/удаление пользователей
- Изменение скриптов
- Изменение настроек приватности

## Ответственность сторон

| Действие | Ответственный |
|----------|--------------|
| Настройка срока хранения | Администратор системы |
| Получение согласия сотрудников | Руководство магазина + HR |
| Установка табличек и настройка индикации | Руководство магазина |
| Безопасность платформы | Команда разработки VoiceIQ |
| Хранение данных в РФ | Команда разработки VoiceIQ |
| Реагирование на запросы субъектов ПД | Администратор + юридическая служба |

---

## Права субъектов персональных данных

Клиенты и сотрудники вправе:
- **Запросить информацию** о том, какие их данные хранятся
- **Потребовать удаления** своих данных
- **Отозвать согласие** (для сотрудников)

**MVP:** автоматизированная обработка запросов на удаление ПД в MVP **не реализована**. Запросы обрабатываются вручную (администратором через `admin-service`). Функция самостоятельного удаления данных субъектом через интерфейс запланирована в будущих версиях.

Обработка таких запросов — на стороне оператора (компании-клиента VoiceIQ). Технически: администратор может вручную удалить конкретную запись и связанные данные через `admin-service`.
