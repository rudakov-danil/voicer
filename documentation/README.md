# VoiceIQ — Документация платформы

> Речевая аналитика для офлайн-розницы. Версия MVP 1.0 | Март 2026

## Что такое VoiceIQ

VoiceIQ — это SaaS-платформа, которая превращает живые разговоры продавцов с клиентами в структурированную аналитику. Продавцы носят небольшие аудиобейджи, которые автоматически записывают каждый разговор. Система сама транскрибирует аудио, оценивает качество работы по скрипту, классифицирует возражения клиентов, определяет исход сделки и выдаёт всё это в виде наглядного дашборда.

**Ключевая идея:** руководитель не слушает записи вручную — система делает это за него и показывает только то, что важно.

---

## Для кого это

| Роль | Что получает |
|------|-------------|
| **Директор** | Сводный дашборд по всей компании: конверсия, скоринг, рейтинг продавцов, алерты |
| **РОП** | Аналитика по назначенным магазинам: сравнение, рейтинг продавцов |
| **Менеджер магазина** | Детали по своей команде: кто как работает по скрипту, управление скриптами продаж |
| **Администратор** | Управление структурой: магазины, продавцы, устройства, настройки |

Каждая компания-клиент — это изолированная **организация**. Данные разных организаций не смешиваются.

## Как это работает — в двух словах

```
Продавец разговаривает с клиентом
        ↓
Аудиобейдж пишет весь день короткими чанками на SD-карту
        ↓
Бейдж на зарядке → dok-станция загружает все чанки через Wi-Fi (recorder-service)
  • каждый чанк содержит badge_token + временны́е метки
  • badge_token сопоставляется с продавцом через admin-service
        ↓
recorder-service: чанки сортируются и склеиваются в суточный файл
        ↓
LLM-сегментация: по транскрипту определяются границы разговоров по контексту
  • каждый разговор физически вырезается и сохраняется как отдельный WAV в MinIO
  • суточный файл и незначимые участки удаляются
  • задача на транскрибацию публикуется в queue.transcribe_full
        ↓
transcription-service: Whisper транскрибирует каждый WAV-файл разговора
        ↓
LLM (diarize_worker): определяет роли — кто продавец, кто клиент
        ↓
analytics-engine: 3-этапный LLM-анализ — скрипты + скоринг + возражения + исход
        ↓
dashboard-service → Redis → frontend
```

Весь процесс — автоматический. От загрузки записи до появления аналитики проходит от нескольких минут до получаса (зависит от длины разговора).

## Ключевые метрики продукта

- **Скоринг скрипта (0–100)** — насколько полно продавец прошёл все этапы назначенных скриптов продаж
- **Конверсия** — доля разговоров, завершившихся покупкой
- **Распределение возражений** — какие возражения встречаются чаще всего и как они закрываются

## Технические решения (ключевые)

| Аспект | Решение | Причина |
|--------|---------|---------|
| STT | Whisper self-hosted | Данные не покидают сервер, соответствие 152-ФЗ |
| Диаризация | Отдельный LLM-запрос с именем продавца | Whisper только транскрибирует, роли — через LLM |
| AI-анализ | Один большой LLM-промпт | Снижает задержку и стоимость по сравнению с 4 запросами |
| Сегментация | LLM-сегментация по контексту транскрипта | Определяет границы разговоров по смыслу |
| Аудиофайлы | Разговоры физически вырезаются в отдельные WAV, остальное удаляется | Нет смысла хранить фоновый шум и тишину |
| БД | PostgreSQL + Redis | Достаточно для MVP, ClickHouse не нужен |
| Мультитенантность | organization_id во всех таблицах | Изоляция данных каждого клиента |

## Архитектурные принципы (кратко)

- **Микросервисы** — каждый сервис отвечает за одну задачу и не знает о внутренностях других
- **Асинхронная обработка** — тяжёлые задачи (транскрибация, AI-анализ) выполняются в фоне через очереди
- **API-first** — все сервисы общаются только через REST API
- **Мультитенантность** — полная изоляция данных каждой организации-клиента
- **Данные в РФ** — вся инфраструктура локально, соответствие 152-ФЗ
