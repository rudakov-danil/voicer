# VoiceIQ (Voicer) — документация

Вся документация проекта в одной папке (собрано 2026-10-17 из бывших `docs/ai/`, `documentation/` и `ТЗ на сервисы/`). Краткая памятка с правилами работы — `CLAUDE.md` в корне проекта; начинать с неё.

## Что это

Речевая аналитика разговоров продавцов, бариста и фармацевтов: кофейни, аптеки, розница, телефонные продажи. Есть клиенты в Казахстане — речь на русском и казахском вперемешку. Запись разговора распознаётся, в ней определяются роли «продавец / клиент», затем LLM оценивает разговор по скриптам продаж, находит возражения, допродажи, неудовлетворённый спрос, нарушения комплаенса и определяет исход. Руководитель видит итог в кабинете (`lk.voicer-ai.pro`, витрины `horeca.` и `pharma.voicer-ai.pro`), сотрудник — в приложении (`mobile.voicer-ai.pro`: смена, советы, монеты). Команда сервиса управляет организациями через консоль техадмина.

**Ключевая идея:** руководитель не слушает записи вручную — система делает это за него и показывает только то, что важно.

## Как это работает

```
Запись: ручная загрузка · телефон сотрудника · бейдж · телефония (вебхук АТС / загрузка звонка) · готовый текст
   ↓ recorder-service: распознавание (ElevenLabs Scribe v2 через OpenRouter; стерео-звонки — Deepgram),
   ↓                   длинная запись режется на разговоры (LLM)
   ↓ diarize-worker:   роли «продавец / клиент» (LLM + голосовые отпечатки ECAPA)
   ↓ analytics-worker: [кофейни: отсев «не гостей»] → скрипты → общий анализ + комплаенс → допродажи, спрос
   ↓ dashboard-service → Redis → кабинет и приложение
```

## Ключевые метрики продукта

- **Скоринг скрипта (0–100)** — насколько полно сотрудник прошёл этапы назначенных скриптов
- **Конверсия** — доля разговоров, завершившихся покупкой
- **Допродажи** — сколько предложений сделано и принято
- **Неудовлетворённый спрос** — чего клиенты просили, но не получили
- **Возражения** — какие встречаются чаще и как закрываются
