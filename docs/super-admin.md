# Консоль технического администратора (Super Admin)

Сделана 2026-10-17 (выкатка 15:37 UTC, бэкап до правки `~/voiceiq-backups/superadmin-20261017-153553`). Изначально планировалась отдельная панель на домене `admin.voiceiq.ru` (приглашения по email, регистрация бейджей по QR, блокировка бейджей по лицензии) — её не сделали; что из этого осталось в планах, см. бэклог в `known-issues.md`.

## Где находится

- Страница: `https://lk.voicer-ai.pro/api/v1/auth/console/<SUPER_CONSOLE_PATH>`. Секретная часть адреса лежит в `.env` сервера (`grep '^SUPER_CONSOLE_PATH=' ~/voiceiq/.env`) и передаётся в auth-service через `docker-compose.yml`. **В документацию и репозиторий не пишется.** Пусто или неверно — 404. Работает и на horeca/pharma-доменах (тот же nginx), не работает на mobile (белый список API).
- Ссылок в кабинете нет, ручки `/api/v1/auth/super/*` скрыты из Swagger. Секретный путь виден в access-логах uvicorn и nginx — логи не публиковать.
- Код: `services/auth-service/app/routers/super_admin.py` (API), `app/static/super_console.html` (страница без сборки, свой JS), `create_super_admin.py`, проверка `tests/manual_super_admin_check.py`.

## Вход

- Учётные записи — `auth.super_admins` (отдельно от пользователей кабинета). Токен `type=super_access` на 8 ч, хранится в sessionStorage вкладки.
- 5 неудачных попыток с одного IP за 15 мин → 429 (счётчик в памяти процесса, сбрасывается при перезапуске).
- Создать техадмина или сменить ему пароль (пароль вводит пользователь в своём терминале):
```bash
ssh -t <алиас сервера> 'cd ~/voiceiq && docker compose exec auth-service python create_super_admin.py admin@example.com'
```
  Дальше техадмины заводятся прямо в консоли.

## Разделы

| Раздел | Что можно |
|--------|-----------|
| Состояние | health всех API-сервисов, записи по статусам, за 24 ч, зависшие > 1 ч |
| Организации | список со статистикой; создание вместе с первым директором (тип, отрасль, валюта, часовой пояс); правка; отключение |
| Пользователи | пользователи кабинета всех организаций: создание, роль (в отличие от кабинета сохраняется), магазин, пароль, отключение; **«Войти как»** |
| Магазины, Продавцы, Бейджи | создание и правка в любой организации. Удаления нет — только отключение |
| Лицензии | лицензии магазинов. Справочные: сервис не ограничивает работу по лицензиям |
| Тех. админы | создание, смена пароля, отключение (себя нельзя) |

## Как устроено

- «Войти как» выдаёт обычную пару токенов кабинета от имени пользователя, кладёт её в `localStorage['voiceiq-auth']` и открывает кабинет в новой вкладке (вход в кабинет в этом браузере заменяется). В лог auth-service пишется `Super admin … signs in as …`.
- Магазины, продавцы, бейджи и лицензии пишутся прямо в `admin_schema` через общий `DATABASE_URL`: admin-service работает только внутри организации из токена.
- Отключённая организация (`organizations.is_active=false`): её пользователи не входят и не обновляют токен (403) — проверка в `_build_token_response` (`app/routers/auth.py`).
- Email пользователей, созданных из консоли, уникален на весь сервис без учёта регистра: вход ищет пользователя по email во всех организациях сразу (`known-issues.md` №22).

## Проверка после изменений

На живой БД, всё в транзакции с откатом (38 проверок, следов не остаётся):
```bash
docker compose run --rm --no-deps -T -e PYTHONPATH=/app auth-service python tests/manual_super_admin_check.py </dev/null
```

## Старая панель sqladmin

В admin-service по-прежнему есть встроенная панель sqladmin «VoiceIQ Admin» (`/admin` внутри admin-service: магазины, продавцы, бейджи, лицензии всех организаций, вход по общему паролю `ADMIN_PANEL_PASSWORD`). Наружу она не открыта: порт 8007 закрыт override, nginx `/admin` отдаёт страницу кабинета. Всё, что она умеет, есть в консоли.

## Чем консоль отличается от кабинета

| | Консоль техадмина | Кабинет (`lk.voicer-ai.pro`) |
|---|---|---|
| Кто | команда сервиса | director / admin / rop / manager организации |
| Данные | все организации | только своя организация |
| Организации | создание, настройки, отключение | своя: тип, отрасль, валюта, пояс (director/admin) |
| Пользователи | все, роль сохраняется | своей организации (смена роли в форме не сохраняется, №23) |
| Аналитика | через «Войти как» | полная |
