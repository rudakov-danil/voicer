# Демо Coffee Shop (horeca.voicer-ai.pro)

Синтетическая сеть из трёх кофеен и восьми бариста. На домене `horeca.voicer-ai.pro` директора и админы
организации Demo входят прямо в неё (auth-service: `DOMAIN_ORGS`, `DOMAIN_ORG_GUESTS`) — отдельная учётка не нужна.

Все цифры в кабинете сходятся с текстом разговоров: каждый заказ генерируется из одного сценария —
диалог, предложения (приём и ответ гостя), чек, этапы скрипта, возражения, нарушения. LLM не нужен.

Сюжет: у бариста разный стиль (сильные, средние, «давит после отказа», новичок, который подтягивается),
в часы пик (8–9, 13) предлагают реже, «Что-нибудь ещё?» почти не работает, лучше всего — предложение
с причиной; товар дня — тыквенный латте; у точки «Белорусская» свой план 60 %.

## Файлы

| Файл | Где запускать | Что делает |
|---|---|---|
| `seed.sql` | postgres | организация, точки, бариста, план смены (70 %, 8 допродаж, товар дня) |
| `install_pack.py <org_id> <user_id>` | scripts-service | ставит отраслевой пакет «Сетевая кофейня»: скрипт, правила, возражения |
| `horeca_demo.py <org_id> <YYYY-MM-DD> [--until=HH:MM] [--dry]` | dashboard-service | пересоздаёт 28 дней заказов; сегодня — до текущего времени по Москве |
| `create_login.py <org_id>` | auth-service | отдельный вход в демо (email и пароль спрашивает в терминале) — обычно не нужен |
| `cleanup.sql` | postgres | удаляет демо-организацию целиком |

## Обновить данные на сервере

Демо привязано к датам: без обновления «Смена сегодня» утром пустая (на экране есть кнопка «Открыть смену …»).

```bash
ORG=c9842e2d-9d12-51ad-8880-08cb67489cac
cd ~/voiceiq
docker cp ~/horeca-demo/horeca_demo.py voiceiq-dashboard-service-1:/tmp/horeca_demo.py
docker compose exec -T dashboard-service python /tmp/horeca_demo.py $ORG $(TZ=Europe/Moscow date +%F)
docker compose exec -T redis sh -c "redis-cli --scan --pattern 'dashboard:*$ORG*' | xargs -r redis-cli del"
```

Скрипт удаляет только разговоры, записи, расшифровки и кэш подсказок этой организации.

## Демо приложения и мотивации

`seed_app_motivation.py` добавляет примеры в существующую организацию `horeca-demo`, сохраняет ID и историю. Он переименовывает три точки в Coffee Shop 01–03 и восьми бариста в казахские имена. Для выбранной даты и предыдущего дня добавляет по 18 заказов на сотрудника, включая расшифровки, предложения, чек и оценки; повторный запуск не дублирует данные и сохраняет принятые решения.

Добавляются демонстрационные версии правил: размер — 5, добавка — 3, выпечка — 10, сезонный латте — 15 монет. У Coffee Shop 02 стоимость выпечки — 12, сезонного латте — 20. Coffee Shop 01 и 03 наследуют правила сети. В балансе есть подтверждённые примеры; также созданы ожидающие, отклонённые и отменённые заявки. В интерфейсе они помечены как вымышленные демо-данные.

Запуск в dashboard-service: `python seed_app_motivation.py --apply --day 2026-10-14`. Без `--apply` выводится только план. Для проверки используется `--database coffee_shop_demo_test`. Скрипт жёстко ограничен организацией `horeca-demo`; другие организации он не меняет. Подготовленные советы разделены по аудитории и обновляются при новых разговорах.

Используйте этот добавочный сценарий для приложения с монетами. Старый `horeca_demo.py` пересоздаёт историю и не предназначен для обновления уже настроенного журнала мотивации.
